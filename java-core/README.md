# java-core — модуль курса «Практикум по Java для Kotlin-разработчика»

Модуль в шаблоне `backend-template`. В нём уже есть сборка (Gradle, JDK 25,
JUnit 6), заготовки и **готовые тесты** уроков, которые сдаются pull request.
Тела, которые пишете вы, — `throw new UnsupportedOperationException("Урок N: …")`
или `// TODO`; тесты на старте красные. Задача — сделать их зелёными.

Уроки с задачей в репозитории: **5, 10, 12, 15, 17, 22, 24, 25, 28, 29**. Остальные
уроки курса решаются в песочнице на платформе, в модуле для них ничего нет.

## Как начать

1. Создайте свой репозиторий `backend-<логин>` из шаблона (Use this template),
   клонируйте его. Нужна JDK 25.
2. Запустите тесты урока 5:

   ```bash
   ./gradlew :java-core:testReport -Plesson=05
   ```

   (номер урока можно писать и без нуля: `-Plesson=5`).

   Что увидите: проект собирается, тесты урока падают, отчёт появляется в
   `java-core/reports/tests-05.txt`.

## Модуль в существующем репозитории

Если вы подключаете `java-core/` в уже созданный `backend-<логин>` командой
`git checkout template/main -- java-core`, добавьте в `settings.gradle.kts`
строку `include("java-core")`, а в корневой `build.gradle.kts` проверьте плагин
`kotlin("jvm")` (версия — как в шаблоне). CI берётся из `.github/workflows/java-core.yml`.

## Устройство

| Что | Где |
|---|---|
| Код урока NN | `src/main/java/lessonNN/` (уроки 28 и 29 — ещё `src/main/kotlin/`) |
| Тесты урока NN | `src/test/java/lessonNN/` |
| Тесты, которые пишете вы (10, 12, 15, 17, 24, 25) | пустые классы в `src/test/java/lessonNN/` — имя дано, содержимое ваше |
| Образец на Kotlin для урока 5 | `samples/lesson05/Course.kt` (не компилируется) |
| `pom.xml` урока 28 | `maven/lesson28/pom.xml` |
| Отчёт прогона | `reports/tests-NN.txt` — коммитится в pull request; свой отчёт урока — `reports/lesson-NN.md` |
| Карта вопросов собеседования | `reports/java-interview.md` |

На машине без JDK 25 временно: `./gradlew :java-core:testReport -Plesson=05 -PjavaToolchain=24`.

## Как сдавать

- ветка на урок — `java-NN` от свежего `main` (`java-05`, `java-10`, …);
- в pull request — файлы урока и свежий `reports/tests-NN.txt`; строка урока в
  `reports/java-interview.md`;
- заголовок начинается с кода задачи: `JAVA-05-1`, `JAVA-10-1`, …;
- для уроков 10, 12, 15, 17, 24, 25 в pull request виден и отчёт **до** правки
  (тест краснеет на выданном коде), и отчёт после;
- репозиторий публичный, после приёмки pull request вливаете в `main` сами.

CI (`.github/workflows/java-core.yml`) берёт номер урока из имени ветки,
перегенерирует отчёт и падает, если он не совпал с закоммиченным или в нём есть красные тесты.
